# Fashion Tours — премиальный сайт турагентства

Премиальный брендовый сайт для турагентства Fashion Tours: моушн-анимации, скролл-история, редакционная (fashion-журнал) эстетика.
Статус: подготовка. Ждём ответов на бриф, затем мудборды → прототип → разработка.

- Бриф (живой документ, ответы заказчика): https://claude.ai/artifact/TpbaWYbodkVDK3kcCXyfEW
- Исходные материалы команды (интервью, фактура) — НЕ в репозитории: репо публичное, а там личные данные и истории клиентов. Запросить у пользователя повторно, если нужны.

## Суть проекта

- Fashion Tours — онлайн-турагентство. Лицо бренда — Наталья (на сайте обязательно её лицо), но агентство говорит «мы».
- Фокус: **премиальный отдых в Турции и индивидуальные маршруты по стране** (Каппадокия, Эгейское побережье, Бодрум, Стамбул; яхты — только после подтверждения продукта).
- Аудитория: семьи с детьми и пары, ~27–55 лет. Трафик в основном тёплый (знают Наталью), возможен тест контекстной рекламы. Большинство — с телефона.
- Главная идея визуала (гипотеза): скролл-история «сборы → полёт → прилёт → вид с террасы», после неё — форматы Турции, Наталья, обзоры, процесс, отзывы, обращение.
- Требование Натальи: «быстро зашли, нажали заявку — заявка улетела». Красота не мешает конверсии.

## Жёсткие правила контента (не нарушать)

- Не выдумывать отзывы, кейсы, цифры клиентов, рейтинги, награды, состав команды.
- Не писать: «24/7», «ответим за час», «все отели проверены лично», «лучшая цена», «апгрейд каждому», «гарантируем», «работаем только от N ₽».
- MICE, Мальдивы, Азия не перебивают Турцию; MICE и яхты — не как доказанная специализация.
- Стоки и AI-изображения — только как атмосфера, никогда не как «наши туристы» или личные поездки.
- Нет материала → видимый подписанный плейсхолдер («портрет Натальи», «реальный отзыв — уточнить»).
- Название пошло от отеля Fashion TV в Кемере — партнёрства нет, не упоминать как связь.

## Принципы дизайна и моушна

- Одно основное действие на первом экране (не три равнозначных CTA). Кнопка обращения доступна на всём пути.
- Скролл всегда под контролем пользователя: без скролл-джекинга и длинных принудительных последовательностей.
- `prefers-reduced-motion` → статичная версия с тем же содержанием. Звук только по клику.
- Первый экран и CTA работают до загрузки тяжёлых медиа; сцены грузятся лениво.
- Мобильная версия — отдельная постановка (кадрирование, длина истории), а не ужатый десктоп.
- Цели: Lighthouse mobile ≥ 90, LCP < 2.5 s, 60 fps на среднем телефоне, WCAG 2.2 AA.
- Кириллица обязательна во всех шрифтах.

## Предлагаемый стек (утверждается в брифе, блок Ж)

Next.js (App Router) + TypeScript + Tailwind · GSAP + ScrollTrigger · Lenis · Motion · Three.js при необходимости.
Хостинг с доступом из РФ; аналитика — Яндекс Метрика. Юр. страницы под 152-ФЗ.

## Установленные скиллы и плагины

Плагины объявлены в `.claude/settings.json` (scope: project) — подтягиваются в новой сессии автоматически.
Отдельные скиллы лежат в `.claude/skills/` (версии — в `skills-lock.json`).

| Задача | Что использовать |

| Дизайн-система, палитры, шрифты, UX | `ui-ux-pro-max`, `claude-web-skills`, `example-skills` (frontend-design, theme-factory, canvas-design) |
| Awwwards-стек (GSAP + Lenis + Next.js) | `lume` |
| Веб-анимации, микровзаимодействия | `cg-web-animate`, `animate`, `animation-principles`, `transitions`, `kinetic-typography` |
| Арт-дирекция, раскадровка сцен, цвет | `creative-direction`, `motion-art-direction`, `shot-composition`, `color-motion`, `motion-design-studio` |
| Видео для сцен / соцсетей (Remotion) | `remotion-video`, `remotion-motion`, `cinematic-video`, `social-video`, `motion-background`, `logo-animation` |
| Тексты, конверсия, маркетинг | `marketing-skills`, `product-skills` |

| Процесс (планирование, TDD, ревью) | `superpowers` |

Внимание: `superpowers` и `jmrsquared-standards` добавляют SessionStart-хуки, которые подмешивают в контекст свои правила.
Правила этого файла и решения пользователя имеют приоритет над ними.

## Рабочий процесс

1. Бриф (пользователь отвечает в документе по ссылке выше).
2. 2–3 мудборда-направления живыми страницами → пользователь выбирает одно.
3. Прототип: первый экран + скролл-история → утверждение ритма.
4. Дизайн и разработка всех секций + мобильная версия.
5. Замена плейсхолдеров реальными материалами Натальи.
6. Запуск: домен, аналитика, тест вариантов CTA.

Дизайн-решения опираются на ответы пользователя и скиллы; материалы команды — источник фактов, а не макет.
